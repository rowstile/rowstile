# AZ721: A SCIM request the endpoint doesn't serve

`authz.scim` answers an identity provider's request with a status and a body, and a refusal is an answer too, never an error: its body is SCIM's own error (RFC 7644, 3.12), whose `detail` ends with this code. 401: the bearer token is not an API key of the principal the settings name (`authz.set_scim`), or that key was revoked, expired, or its principal is no longer active. 403: the key is limited to scopes that write nothing, and the request changes something. 404: no such user or group, or a path nothing is served at. 405: a method the path doesn't take. 400, with SCIM's `scimType`: a filter other than `attribute eq "value"` joined by `and` (`invalidFilter`), a PATCH without `Operations` or with an `op` that is none of add, remove and replace (`invalidSyntax`), a remove without a path (`noTarget`), a path that is nothing a PATCH changes here or that isn't read (`invalidPath`), a member that is no user, a group without a name, a user without a `userName` (`invalidValue`). 409 (`uniqueness`): a `userName` another user has. 501: the settings name no group, no column for a user's `userName`, or no function of the app's to make, change or delete one (`group_function`, `user_function`). A refusal changes nothing: a request is done whole or not at all. What the app's own function refuses is answered 400 with its words, and a name or a key another row has 409 (`uniqueness`), without this code.

Reported to the identity provider, in an answer of `authz.scim`: the code ends the `detail` of SCIM's error body (`rowstile help AZ721`).
